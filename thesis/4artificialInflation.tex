\section{PPO and its Variants}

Before getting into our implementation details, we want to explain the basic construction
of PPO. Introduced by Schulman et al. in 2017 \needcite{65 schulman}, it is an actor-critic algorithm,
which means it consists of an actor, guided by a policy, that is simulated in an environment,
and a critic, which tries to estimate the underlying value function based on the current policy
and the actors returns\needcite{62 Konda}. In the case of PPO, as we're trying to optimize a policy
via policy gradient optimization, we "[construct] an objective function whose gradient is the policy
gradient estimator" \needcite{65}. What makes PPO special is the construction of this surrogate
function, based on ideas from Trust Region Policy Optimization \needcite{63}. 
In the paper, two approaches are proposed: Clipped Surrogate Objective or Adaptive KL % TODO: explain KL and prob ratio
Penalty coefficient. The former clips the probability ratio past a limit set by a hyperparameter,
imposing constraints on the policy update size\needcite{65}, while the latter, rather than setting
a fixed KL for an update, sets a target KL divergence\needcite{65}. In case further interest
arises, we refer to the original paper here\needcite{65}.

However, as has been noted before \needcite{66, 68}, the actual implementation of PPO matters,
and can influence the effectiveness of it in practice. For our construction, we use
the architecture provided by StableBaselines3\needcite{https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html}.
As the standard architecture, for our MLP PPO, we use the standard 2-layer with 64 neurons approach for both
actor and the critic \needcite{https://stable-baselines3.readthedocs.io/en/master/guide/custom_policy.html}.
Additionally, unless named otherwise, we will use the standard parameters from the SB3 library.
For the above named parts, we leave the clip range at the standard of 0.2 and set the target kl to 0.02.

Still, we want to stay in line with the idea of encoding our observations into a latent state, as this exactly introduces the bow-tie structure

are prior knowledge, like physical laws, from which we define loss functions. By adding them to the training process, and optimizing for them, we can
ensure that learned representation is in line with these laws. As mentioned in \needcite{cref to appraoch}, this allows us to make use of the embodiment
to improve our controller architecture. Here, we will use the following priors\needcite{Botteghi2021LowDimensional}:

- simplicity: State is lower in dimensionality than the observation
- temporal coherence: States changes are rather slow
- proportionality: Same actions should show similar output strength
